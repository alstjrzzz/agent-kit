## 목적

도구를 사용하는 작업에서는 사용자가 따로 요청하지 않아도 이 스킬을 기본으로 적용한다. 목적은 탐색 자체를 제한하는 것이 아니라, 메인 대화와 메인 터미널에 불필요한 명령어·diff·로그·중간 결과가 노출되지 않도록 작업을 격리하고 최종 결과만 간결하게 보고하는 것이다.

순수한 설명·번역·아이디어 정리처럼 터미널이나 파일 도구를 사용하지 않는 대화에는 적용하지 않는다.

## 기본 적용 범위

다음 작업을 포함해 터미널, 파일시스템, 코드, 설정, 저장소를 확인하거나 검증하는 작업에는 이 스킬을 먼저 적용한다.

- 파일 읽기·검색·비교, 코드 diff와 저장소 상태 확인
- 빌드, 테스트, 린트, 패키지 설치와 같은 명령 실행
- 설정·로그·프로젝트 구조 조사
- 구현 후 변경사항 검토와 검증 결과 확인

## 격리 실행 — 기본 동작

subagent/delegation 기능이 제공되면 터미널·파일 탐색·저장소 확인·diff·명령 실행·검증 작업은 **항상** subagent에 위임한다. 이것은 선택 사항이 아니다. 메인 에이전트는 작업 범위와 최종 보고 형식만 전달하고, 원본 터미널 로그를 메인 대화에 출력하지 않는다.

subagent가 완료되면 결과를 받고, 성공 여부·핵심 차이·실패한 명령만 요약한다. 사용자에게 내부 위임 방식이나 도구 이름을 설명하지 않는다.

다음 작업은 원본 출력을 메인 대화에 붙이지 않는다.

- `git diff`, `git log`, `git status`처럼 결과가 길어질 수 있는 코드·저장소 확인
- 빌드, 테스트, 린트, 패키지 설치처럼 로그가 많이 나오는 명령
- 여러 파일을 검색하거나 여러 명령을 이어 실행해야 하는 코드베이스·설정 조사
- 버그 원인 추적, 실행 흐름 확인처럼 중간 결과보다 최종 결론이 중요한 작업
- 사용자 요청을 구현한 뒤 변경사항과 검증 결과를 요약해서 보고해야 하는 작업

subagent 지시에는 확인할 범위와 최종 보고 형식을 명확히 적는다. 원본 터미널 로그를 그대로 붙이지 말고, 성공 여부·핵심 차이·실패한 테스트나 명령처럼 결과에 필요한 내용만 요약하도록 요청한다.

실제 파일 수정은 현재 작업 공간의 변경 상태와 사용자 확인이 필요하므로 기본적으로 메인에서 처리한다. 수정 후 diff·빌드·테스트 검증은 subagent에 위임한다.

## subagent를 사용할 수 없는 예외

subagent/delegation 기능이 실제로 없을 때만 메인에서 실행한다. 그 경우 subagent로 격리했다고 말하지 않는다.

- 출력 범위를 제한하고, 긴 결과는 요약·통계·상태 코드만 표시한다.
- 긴 로그와 전체 diff는 임시 파일로 보내고 필요한 부분만 읽는다.
- 여러 명령을 한꺼번에 실행하지 말고, 필요한 확인만 최소 단위로 실행한다.
- 사용자에게는 격리되지 않았음을 숨기지 않고, 결과만 간결하게 보고한다.

subagent/delegation 기능이 있는데도 메인에서 직접 실행하지 않는다. 사용자가 실시간 출력이나 페어 작업을 명시적으로 요청한 경우만 예외다.

## 메인에서 직접 실행할 작업

subagent가 있더라도 다음은 메인 대화에서 직접 실행할 수 있다.

- 파일 하나를 읽거나 짧은 검색 한 번으로 끝나는 확인
- 사용자가 명시적으로 실시간 출력이나 페어 작업을 요청한 경우
- 실제 파일 수정처럼 대화 중 판단과 사용자 확인이 필요한 작업

실행 결과가 예상보다 커지면 subagent에 위임한다. subagent를 시작한 뒤에는 결과를 추측하지 말고 완료 알림을 기다린 다음 결론만 보고한다.
