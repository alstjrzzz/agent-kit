## fork로 탐색하기

git log 뒤지기, 버그 원인 추적, 코드베이스나 설정 서베이처럼 결론에 이르기까지 여러 차례 툴 호출(bash, grep, read)이 필요하고, 그 과정 자체는 나중에 다시 볼 일이 없는 작업이다. 이런 작업을 메인 대화에서 바로 실행하면 중간 툴 호출 결과가 그대로 터미널에 쌓여 스크롤을 어지럽힌다.

### 적용 대상

- "왜 이렇게 됐는지 찾아줘", "이 흐름이 어떻게 동작하는지 추적해줘"처럼 결론 도출에 여러 라운드의 탐색이 필요한 작업.
- 사용자가 과정이 아니라 결론만 궁금해하는 작업.

### 적용하지 않는 대상

- 사용자가 실시간으로 지켜보며 방향을 바꿀 수 있어야 하는 직접 구현/수정 작업.
- grep 한 번, read 한 번으로 끝나는 단발성 조회. fork 오버헤드가 아깝다.
- 사용자와 실시간으로 같이 조사하는 페어 작업.

### 하는 일

`Agent` 툴을 `subagent_type: "fork"`로 호출한다. fork는 지금까지의 대화 맥락을 그대로 물려받아 백그라운드에서 실행되고, 그 안에서 발생한 툴 호출 결과는 메인 대화/컨텍스트에 노출되지 않는다. 완료 알림과 함께 요청한 요약만 돌아온다.

- fork 프롬프트는 지시문으로 쓴다. 이미 맥락을 물려받았으므로 배경 설명을 반복하지 않는다.
- 몇 줄 이내로 결론만 보고하라고 명시적으로 요청한다.
- fork를 실행시킨 뒤에는 결과를 추측하거나 미리 말하지 않는다. 완료 알림이 올 때까지 기다린다.
- fork가 끝나기 전에 사용자가 후속 질문을 하면, 아직 실행 중이라고만 답한다.
- 서로 독립적인 탐색이 여러 개면 한 메시지에서 병렬로 여러 fork를 띄운다.
